# Working philosophy

[English home](../../README.md) · [中文](../philosophy.md)

This framework serves one purpose: help AI continuously solve real problems for the user, return useful conclusions and usable deliverables, and reduce repeated explanation, correction, and manual work.

## Understanding is an ongoing process

The user's intent often develops over time. They may begin with a long-term idea, then add conditions, correct a cause, give an example, or change the scope. The current AI must connect the project core, active task, existing deliverables, and the entire new message to distinguish requirements that remain valid from those explicitly replaced.

A local addition does not automatically replace the complete deliverable. Multiple matters in a voice message must each be addressed. Evidence can overturn the user's proposed causes and methods, while the requested result and conditions must be preserved. When the goal actually changes, update the affected work accordingly.

## External knowledge informs understanding and execution

For an unfamiliar problem, first investigate what others actually solve, how they organize the work, what conditions it requires, and what failures they have encountered. Research can correct the initial understanding of the task. Avoid choosing a route out of habit and then researching only how to implement it.

Search results, titles, model suggestions, and local experience provide leads. Read the original text of key sources that could change a decision, and connect them to the current object's responsibilities, inputs and outputs, applicable conditions, and real state. Mature implementations can reduce repeated exploration, and new evidence can reopen routes previously set aside.

The host AI, search tools, and domain capabilities provide these abilities. This repository publishes related general search, source-reading, and research skills. The current AI still chooses queries and sources according to the task; the installation list does not define all possible candidates.

## Discussion produces methods; assignments produce deliverables

During discussion, provide evidence-based, feasible proposals that the user can judge. After an explicit assignment, continue research, implementation, persistence, and completion without requiring the user to direct every routine action. Return a specific question to the user only when personal information, actual access rights, or a choice about the experience is missing.

When blocked, first restore a usable result, then trace and fix the cause. Explain actual limitations clearly and keep looking for applicable routes. Do not present an unobtainable result as completed.

## AI makes judgments; programs perform deterministic operations

Programs handle files, indexes, versions, concurrent writes, and format processing. AI understands objects, interprets meaning, selects methods, and integrates deliverables. Rules serve actual work. Counts of mechanisms, fixed roles, and self-awarded scores do not show how well the system works.

Keep always-present material concise and retrieve additional material through navigation as needed. By default, do not add testing, benchmarking, or review stages. Actual checks follow the assignment and unknowns that would affect the next step. The user judges writing, interfaces, and other experiences; AI verifies technical facts.

## Experience has conditions and can be corrected

Successful experience, failure causes, knowledge explanations, and object states have different responsibilities. Each experience record preserves its trigger conditions, method, observed result, boundaries, and sources. Recheck applicability when using it, rather than turning one success into a fixed action for every task.

Error records help the next attempt succeed. When failures repeat, correct the step that creates them. Obsolete content leaves active entry points while necessary recovery material remains available.

## Deliverables belong to projects; executors can change

Projects preserve long-term results. Branches preserve current complete tasks. Files preserve decision reasons, progress, deliverables, and unmet requirements. A new executor reads the same source records to take over, without requiring the original conversation or agent to remain active indefinitely.

After a task is complete, integrate useful content, maintain indexes, and handle replaced materials. Creation, use, and maintenance together form a delivery. Judge effectiveness by whether actual work has fewer omissions, rework, and repeated corrections.
