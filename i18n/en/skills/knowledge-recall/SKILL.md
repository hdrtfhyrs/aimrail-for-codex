description: Find and reuse local knowledge and successful or failed experiences by specific object, purpose, and operation, or update useful cases from research, execution, and corrections. Diagnose beyond output symptoms alone; search externally first when no applicable method is available.
---

First consult short navigation for existing material: the local knowledge index (`workspace/memory/knowledge/INDEX.md`), experience and error navigation (`workspace/memory/INDEX.md`), and the relevant project's core, branch relationships, and outcome index. When system configuration, accounts/entitlements, or capability declarations matter, use `node integrations/context/resources.mjs navigation` to find material entry points, then expand declarations and original evidence according to purpose. Reuse complete, applicable navigation already received; do not require reading the entire library or exclude approaches absent from navigation. Run all `node` commands from the repository root. The workspace indexes, domain explanations, recording guidance, and interface-agreement document named here are deployment-specific original locations, not documents included in this sanitized public checkout; configured runtime files may live elsewhere. Their purposes and required record contents are retained below. Do not infer that omitted private records exist in a fresh installation.

Follow “Understand the current task” in the [shared rules](../../integrations/AGENTS.md) for the order of understanding. This skill retrieves object knowledge, experience, and original evidence that contribute to understanding. Local candidates do not bound workable approaches. If outside knowledge is needed at the understanding stage, proactively fill it through `evidence-research` before deciding responsibilities and inputs/outputs. The AI judges additions, examples, corrections, and scope changes in complete context. Actions on old cards are not new instructions or authorization. Source projects help establish conditions and evidence, without restricting reuse across projects or agents.

Identify the specific object being judged, its current responsibility, and the actual operation before forming a query. For example, establish what task an expression-generation model receives, or which loop and conditions output data passes through; do not search only for “generation went off track” or “incorrect output.” Read originals for the object's training purpose, interface, state, and restrictions; labels only help locate material. After finding experience, connect its conditions to the current input/method item by item and specify which judgment or action it changes. Reading without adopting does not count as reuse. If the cause is unclear, trace the actual process with the [diagnostic method](../evidence-research/references/diagnosis.md) in `evidence-research`; matching an old case does not prove the same cause.

When task understanding involves a new object, changed purpose, or real-world change, use `node integrations/context/objects.mjs recognize --query "Name" --purpose "Current use"` (or `--id ID` for a known identity) to retrieve initial existing understanding: concrete properties, category commonalities, relationships, source changes, and unknowns. Defaults are 12 pointers per page and a 24000-character budget for complete node bodies. `reading` explicitly reports read items, budget-deferred items, items outside depth, and next-page counts. Continue using `reading.next` parameters or the target ID; the current page is not full domain coverage. Source `readPointer` returns only path/URL, citations, and paragraph locations. `contentReturned:false` means original evidence or a long domain document has not yet been obtained; use current file/web tools to read actual content before deciding adoption. Resolve same-name ambiguity by establishing identity. For an unfamiliar name, return lexical candidates and category navigation rather than automatically creating an object or guessing a category. Budgets control material reading, not cognitive scores or fixed understanding forms. Reuse existing understanding of old, known, low-impact operations under current conditions without rereading the whole set.

Proactively research category commonalities and concrete differences that affect judgment through object categories, operating mechanisms, and real uses. Do not wait for errors or for the user to point out each item. Full expansion remains available through `expand --id ID [--depth N]`, which obtains ancestor categories, related bodies, `knowledgeGaps`, and unexpanded relationships. For broad relationships, progressively retrieve pointers first. Gap lists cover only registered and read material; the AI must also discover unregistered connections. For example, model architecture connects to total/active parameters, quantization, and memory, while training purpose connects to input methods and task allocation. Preserve these causal relationships and conditions, rather than merely collecting terms or applying example properties to every similar object. Follow “Object understanding and knowledge use” (`workspace/memory/knowledge/对象认识与知识使用.md`) for the overall approach and the current interface agreement (`modules/system/资料中心/object-knowledge/接口约定.md`; consult the deployed document or actual CLI help) for commands and boundaries. Chinese filenames are actual shared interfaces and remain unchanged.

Return new understanding promptly to the active object library: add common properties to the existing category, add knowledge reusable across categories to concept objects with evidenced relationships, and leave specific parameters, responsibilities, and state on specific objects. Use the original versioned save/import interface to retain sources, conditions, and unknowns; do not establish a second registry. Merge existing records first. The current AI judges whether the knowledge is sufficient for the actual use and may fill adjacent gaps together. Require no fixed search count or expansion depth, or resolution of every unknown in a category before execution. Subsequent similar objects reuse category knowledge; recheck only differences and changes.

Read relevant originals directly through navigation, or use `node integrations/context/recall.mjs search --query "Complete current task or symptom"` to search knowledge, experience, errors, objects, resources, and outcomes together (literal + semantic; default 10 items with a total count; paginate through `--offset`). When the user speaks, the hook already delivers the first few candidates based on their words. Expand selected knowledge cards with `node integrations/context/knowledge.mjs load --refs "Selected ID"`. Keyword matches and a small automatic candidate set are leads, not the only entry point, adoption decision, or research coverage. For missed retrieval, continue through indexes, known paths, or revised queries. The current question determines reading volume. If the `load` budget is insufficient, increase it according to the returned required character count or continue over the original's relevant range. A fragment is not a complete card.

Before adoption, establish the experience's applicable conditions, actual results, and original evidence. For configuration declarations, distinguish authorization, existing entitlement, accessibility, and actual operation. Successful experience may solve only a local part; a failure cause or old fix may already be obsolete. If no method applies, conditions differ, or key evidence is missing, prioritize external search. For selection or changing methods/effects, translate the current task and conditions into research questions through [evidence-research](../evidence-research/SKILL.md), examine mature methods, real feedback, and failure conditions in that domain, and let evidence change the current method. Having local experience does not remove the need for external evidence that can change the choice. Switch routes if searches are irrelevant or an entry point fails. Scripts list, query, read, and persist material; the AI makes selections and technical judgments. Report methods actually adopted or declined, why, and remaining evidence gaps; successful retrieval does not establish understanding or long-term effects.

Correct or retire active content confirmed superseded or useless within authorization, preserving the reason, replacement reference, and one cold recovery copy. Personal maintenance uses `integrations/context/system-maintenance.mjs`; do not recursively delete. Retirement through `knowledge.mjs` removes material from recall; explicitly use `include-retired` for historical tracing. Do not discard still-valid experience by age. After compaction or on handoff, new executors judge what to read for their own task; material read by the parent is not automatically read by the child.

When research changes a method, an actual action solves a problem, failure exposes reusable conditions, or user correction revises an old action, proactively retain the parts that change future work in the active system. Update domain facts in existing knowledge explanations or material originals. Save concrete experiences according to recording guidance (`workspace/memory/errors/WRITING.md`), retaining trigger, conditions, action, real results/boundaries, and original evidence. Search comparable cases first and update rather than duplicate. Progress relevant only to the present task stays in project state. Do not create experience records for calls or conversations with no new use, or require a summary every turn.

For confirmed successful facts, `node integrations/context/knowledge-record.mjs --input "Fact JSON path"` can generate a short card and index. For independent conditions, pending-verification status, or edits to old cards, reuse `listCards/readCard/saveCard` in the [shared knowledge service](../../../../modules/system/资料中心/knowledge-service.mjs). Read the current original before saving; update with the returned `ref/version` and retain a backup. The service writes directly to the original `experiences/errors`, not a second library. Maintain aggregated old cards at the relevant location in their original files. Clearly mark unresolved or unverified fixes as pending verification. For locally established cases, leave unverified long-term parts in the boundaries. After saving, confirm that the active index/retrieval can obtain the body; judge technical effects through original evidence and actual use.

For methods reusable under the same conditions, update the relevant active skill within authorization using `skill-creator`; install or use that official host skill separately, because its third-party original package is not included here. Turn only repeated deterministic operations into scripts. Cases retain concrete evidence; skills retain only methods and applicable conditions that change future actions. A single case or third-party suggestion does not directly become a universal rule. Later use updates the same original with new results and corrections, replaces affected old actions, and retains recovery material. For unconfirmed claims, add boundaries only; do not fabricate failure causes. In the next task, still select from the complete goal, read originals, and judge adoption. Storage, retrieval, or model self-evaluation does not prove long-term improvement.
