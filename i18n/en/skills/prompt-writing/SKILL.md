---
name: prompt-writing
description: Write or compress task instructions and generation prompts for subagents and other models. Retain necessary information according to the recipient's capabilities and reduce irrelevant requirements. Ordinary chat explanations and deterministic tool arguments do not require this skill.
---

First follow “Understand the current task” in the [shared rules](../../integrations/AGENTS.md). Connect the full message, project, and needed outside knowledge to form the current task, then decide whether the instruction is for execution, generating material, or delivering a finished result. If a workbench or workflow exists, read the actual operation files relevant now. Use the recipient's known capabilities to establish input, output purpose, and handoff; a preconceived prompt must not constrain understanding in reverse. When the user changes responsibilities, replace affected operations too. Give file entry points when the recipient can read them, otherwise supply necessary content. Prompts guide behavior but cannot guarantee strict compliance by models of any size.

For autonomous executors, instructions mainly supply the shared task/project-progress entry point and the result to change now. The executor first understands user intent and how this task relates to the overall goal, then independently researches, chooses an approach, and finishes. Do not copy accessible background into long instructions. The coordinator's envisioned implementation is not automatically mandatory. Clearly establish necessary file ownership, settled conditions, and actual interface requirements. Mark the coordinator's technical advice as adjustable, while retaining user-specified methods and deterministic operations as required.

The coordinator may give direction and concrete advice, explaining the problem addressed and its evidence. The executor understands its purpose in the complete task, then judges adoption or adjustment. Proactively inspect originals or communicate when key information is unclear rather than copying mechanically. Instructions should let the recipient form an executable understanding. Brevity must not prohibit advice; acknowledgement, repetition, or claimed understanding does not replace actual work.

After completion, subsequent delegation, rework, and cross-stage handoff default to a clean new executor. Instructions must not depend on the predecessor's history or continued availability. Shared originals carry the complete task, necessary evidence, outcomes, unmet items, and discussion. The AI fills material gaps; include necessary prose only if the recipient cannot read files. Where internal `spawn_agent` supports it, explicitly set `fork_turns="none"`; still send live corrections to the current responsible executor. Instruction length follows necessary information, with no fixed word count and no loss of intent for brevity.

Use deterministic parameters for tool calls. When a model generates sentences and scenes for later adaptation, give only genre/topic, situation, and useful material, let it expand, then read the original and select/adapt it. Do not prewrite dialogue, action order, and stopping points to force execution of a construction checklist. Still preserve the finished-result scope explicitly required by the user.

Judge actual trials by module purpose: for execution, whether the work is complete; for generated material, what is useful and how to select/adapt it. Do not push every later integration criterion onto a material-generation model. On failure, first check whether the wrong task was assigned, rather than repeatedly adding rules or blaming the model. Word counts, successful interface calls, and self-scores do not establish improvement. Set no universal length limit.
