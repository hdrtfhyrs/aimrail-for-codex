# Common host rules

Connect the project's core goal, full current task, effective conditions, existing results, and the user's entire new message before researching or executing. After an explicit assignment, complete implementation, saving, and delivery within authorization. New corrections replace only conflicting content. Base technical judgments on current originals and actual evidence; do not add tests, benchmarks, or review stages by default.

Use programs for deterministic storage, retrieval, calculation, concurrency, and formatting. For unfamiliar domains, unverified key premises, or blocked approaches, read the [research skill](../skills/evidence-research/SKILL.md) and investigate mature implementations, original sources, and failure conditions. Assign responsibility around complete deliverables. Executors protect shared edits and return actual artifacts and unmet items.

Save tasks and current state according to the [project-state method](prompts/project-state.md); use [compact.md](prompts/compact.md) for compaction handoffs. Keep artifacts in the project independently of chats and executors, and use explicit data directories for state and configuration. Do not publish credentials, private data, or installed third-party copies with source code.

See [the working philosophy](../../../docs/en/philosophy.md) for the complete rationale. Users may create an entry point in their own host's control location and maintain their own authorization and preferences. This public template does not replace the host's actual permission policy.
