# 把事情讲明白

编写或改写实质文档正文时，在写作阶段读取；绘制用于解释流程、职责或关系的图时，在决定节点、连线和布局前读取图组织要求。图放在聊天、文档还是软件界面，以及是否伴随长篇正文，都不改变这个构图时机。同一执行者可以完成实现和表达，不为使用技能单独派人；无图的短交付无需因此提前加载。

先理解读者为什么要看：他想知道发生了什么、怎样运作、该怎么做，还是要比较并作决定。结合完整任务、有效条件和原材料决定展开深度；已有材料能回答的就直接写，不把成文变成逐节问答或等待批准。

在铺开正文前，先确定读者最需要看懂的关系和结果。复杂内容优先给能解释这些关系的图或可直接比较的表，再展示实际成品、前后变化或真实例子。每张图围绕一个主要问题选择内容，不从正文抽出一串名词逐个装框。讲一件事怎样完成时，沿输入、动作和输出组织主线；讲谁负责什么时，按职责及交接组织。需要同时表达多种关系时，用泳道、分区或明确标注让读者区分，次要关系可放在配图、表格或正文。

节点使用读者能理解的动作或对象名称，流程节点保持相近的步骤层次，不把负责人、存储位置和整套任务当成并列步骤。同一种连线保持明确的含义；顺序、资料传递、支持和反馈不能靠无标注的同一种箭头混在一起。重要交接写明传递什么，分支写明条件；反馈回路说明什么结果会改变上游哪一步。布局服从阅读顺序和显示宽度，主线起点、方向及结果要看得出来；横排、竖排或其他布局按关系选择，不为塞全内容缩小文字或拉成长链。资料很多时按真实关系分组，不把长文缩小塞进图片，也不把互不相连的方框当成整体说明。简单问题直接讲清，不为出图添工序。

先把实际关系理清，再选择画法：什么输入或事件开始，怎样进入下一步，等待条件是什么，什么结果让循环回到哪一步。带有持续状态的流程，要区分进入、维持和退出该状态的条件；状态期间的咨询、提醒等事件，放在该状态内或相关正文中，独立分支则标清触发和去向。节点与箭头据此生成，让读者沿主线看见事情怎样完成。

普通静态流程和关系图优先用简洁的方框、箭头与必要条件，直接在Markdown中用Mermaid表达。默认采用简化风格，避免装饰性卡片、卡通图案和额外展示页面。需要交互、动画、空间演示，或用户明确要求网页时，再选相应形式；用户指定的风格优先。

开头直接回应读者要看的东西。用户要看作品、原稿、改稿或运行效果时，先直接展示实际内容，再说明判断；要求完整原稿就全文原样展示，保留重复、错误和上下文，不能用摘句、摘要或文件链接代替。比较修改时把原稿和修改稿分别标明来源，改动是否更好由实际内容和用户判断，不能因模型被称为“强”就默认其改写有益。

说明结果及其意义时，将会影响理解或下一步的失败、未完成部分、适用范围放在正文可见的位置。一次试验、一个候选、配置已保存、实际已运行和长期有效分别如实说清。

围绕读者的同一个问题推进全文。每段接住前面的信息，补上必要的原因、例子、结果或下一行动；标题下面写连贯的实际正文，不把文章拆成一串摘要和要点。说明谁做了什么、为什么这样做、带来什么结果，保留有实际作用的连接词，不为短句省掉主语、条件和因果，也不靠“首先、其次”把无关段落硬接起来。

先用读者能懂的动作和结果表达，再在需要操作、查找或准确区分时给术语。必须出现的术语，用当前任务中的具体例子解释它在这里做什么；不要只换成另一个专业定义。例如“模型接线未完成”可写成“模型还没接进写作按钮，按按钮还不能自动生成”。同一概念保持同一种称呼，事实缺口不能靠补造细节填平。名称、数字和参数只在帮助理解或使用时进入正文。

按信息关系选择呈现形式：

| 读者要理解什么 | 优先怎样展示 |
| --- | --- |
| 一件事怎样做完 | 流程图，标明输入、动作和输出 |
| 谁负责什么、各部分怎样联系 | 结构图或关系图，连线说明联系 |
| 几个办法有什么差别 | 相同维度的对照表，或同处前后图 |
| 数量、比例、变化趋势 | 有单位和来源的图表 |
| 软件、图片或文章做成了什么 | 实际截图、运行效果或连续原文 |
| 为什么这样做、成立条件是什么 | 相连的段落，必要时配具体例子 |

图表讲清的关系不逐项再抄一遍；正文补原因、含义和使用方法。标题用于定位真实问题，步骤用于顺序操作。长文可充分展开，不设固定章节、篇幅、句长或禁词评分。用户指定的格式、原模板和作者声音优先。涉及持续状态、混合关系或反馈循环时，按需读 [图文组织与真实改写例子](references/visual-reading.md)；简单静态节点连线图直接用Mermaid，需要交互或其他可视化实现时用当前 task-visualize，导出的图和文档用对应格式工具。

改写时守住原件中的事实、角色、条件、不确定性、重要失败与下一步。读者用来判断的原文和实际结果放在正文；命令、参数、内部接口及追溯细节可移到技术附录并给明确入口，关键限制仍留正文。缺资料时标明未知，不为流畅补造事实。

完成后连着读一遍：读者能否先看懂整体和实际结果，再沿正文理解原因、限制及用法；逐项核对会改变结论的事实与原件。把真实图表和足以判断的连续正文直接展示出来，长文同时打开全文；修改交同处前后对照。路径和完成汇报不能代替成品。读感由用户读成品判断，技术事实由写作者负责，不报告自造分数证明“易懂”。

需要 Word、PDF 或其他格式时，在正文组织完成后使用相应生成、排版和检查工具；这些工具承担格式实现，用户原模板仍有约束力。需要知识库维护时另读 knowledge-docs；此技能本身不授权改库、发布或发送。
