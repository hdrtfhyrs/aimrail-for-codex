# 用图和连贯正文组织说明

## 按图的用途组织关系

先明确图要回答的主要问题，再选择节点、连线和阅读顺序。流程图让读者沿动作看见输入怎样变成输出；职责图让读者看见谁负责什么、向谁交付什么；对比图按同样的对象和维度呈现差异。内容已经画全、节点已经连通，不能证明这些关系已经表达清楚。图中的关键条件和缺口直接标在相关动作或连接旁，原因与采用理由由连贯正文展开。

流程涉及多个负责人时，可把负责人放在泳道标题或步骤短注里；需要说明保存位置时，可标在相关步骤旁。两者不因此成为额外的先后步骤。多种关系必须同图呈现时，使用可辨认的分区、线型及关系标签；关系复杂到遮住主线时，拆成互相衔接的图、表或正文。布局按实际宽度与关系选择，反馈回路只表达真实的返回条件或影响，不用回环表示笼统的“持续改进”。

持续状态不是瞬时动作。例如共享设备使用的示意主线是“取得预约 → 等设备空闲 → 分配使用时段 → 当前使用者使用 → 达到结束条件 → 检查设备并释放时段”，然后回到处理下一份预约。其他人来问预计几点空闲，属于当前使用期间发生的咨询；放在该状态内或正文里，就能看清它发生于何时。若另画分支，需要明确“使用期间收到咨询”这个触发，不能只放一句“后来通知预计结束”让读者猜关系。这个例子说明持续状态与循环的组织办法，具体入口和结束条件仍按当前任务决定。

例如，解释外部资料怎样用到工作里，可以画“寻找来源 → 取得并保存原件 → 研究怎样采用 → 项目采用 → 实际成果”。“知识分支”是职责名称，“原库”是保存位置，“经验回存”是复用关系，不能因为文章提到了它们，就插进同一条先后链。知识维护与项目执行确有交接时，另用职责表或标明交付内容的连线表达。节点文字保持具体，像“研究怎样采用”就能让读者理解动作；“补类别、对象、因果”需要展开它在当前任务中实际改变什么。

## 图与正文怎样衔接

下面是通用文档协作的示意改写，不是实际运行结果。

原文片段：

> 已有一份说明文档候选，自动生成入口还有未完成部分。

假设已有材料说明了四个部分的责任与结果，可以画出“来源材料 → AI助手安排四部分 → 执行者写初稿 → AI助手选择、补写 → 文档候选”；第二部分写偏了，标在初稿这一处；“页面按钮自动调用模型”仍未接通，放在流程下方显示。图中的短标签不改变责任、数量和完成状态。

接着写：

> 说明文档候选已经写出来，可以直接阅读。这次由AI助手安排四个部分，执行者写初稿，再由AI助手选择、修正和补写。第二部分偏离了任务，最终没有采用；助手补写后形成完整候选。现在可以阅读这份文档，但页面按钮还不能自动调用模型。

这段顺着“得到什么 → 怎样做出来 → 出了什么问题 → 现在能用到哪一步”解释同一件事。改写不能把一次候选说成正式采用，也不能把流程图当成程序已自动运行的证据。这里的候选与失败只用于说明保真表达的方法。

## 借鉴来源与适配

2026-10-04读取了作者原件。宝玉的 [信息图](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-infographic) 把内容关系与视觉风格分开选择，[文章配图](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-article-illustrator) 先明确图在哪里、帮助理解什么，[图表](https://github.com/JimLiu/baoyu-skills/tree/main/skills/baoyu-diagram) 给出真实SVG的关系、流程、分层布局方法。借用这些组织方法；准确关系图采用可编辑文字与连线，需要绘画或风格化位图时再用当前图像生成能力。

中文 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh) 的2026-09-23修订强调保留事实和连接关系；[ai-zixun/humanizer-zh](https://github.com/ai-zixun/humanizer-zh) 从全文主线检查段落作用。借用保真改写和全文连贯检查，不采用固定禁词、标点禁用或未经请求的作者模仿。

[visual-explainer](https://github.com/nicobailon/visual-explainer/tree/main/plugins/visual-explainer) 强调首屏图解和每图一个明确问题，借用它的阅读顺序。是否做网页、用多少图、篇幅和格式仍按当前成果与用户要求决定，不照搬“每个数字都画图”等固定门槛。
