name: knowledge-recall
description: 按具体对象、用途和操作查找、复用本地知识与成功失败经验，或更新研究、执行及纠正中的有效案例；诊断不只按输出症状查，缺适用办法优先搜索。

先了解已有材料的短导航：[本地知识目录](../../workspace/memory/knowledge/INDEX.md)、[经验与错误导航](../../workspace/memory/INDEX.md)，以及所属项目的核心、分支关系与成果索引。系统配置、账号/权益或能力声明有关时，用 `node integrations/context/resources.mjs navigation` 了解资料入口，再按用途展开声明及原证。已收到完整且适用的导航可直接使用；不要求先读全库，不把导航中未出现的办法排除。

任务理解顺序沿[共同规则的“理解当前任务”](../../integrations/AGENTS.md)。本技能取得参与理解的对象知识、经验与原证；本地候选不是可用办法的边界，理解阶段需要外部认识时主动沿evidence-research补齐，再决定实际分工与输入输出。补充、例子、纠错与范围变化由AI结合完整语境判断；旧卡动作不构成新指令或授权。来源项目用于核对条件和证据，不限制跨项目、跨代理复用。

先识别正在判断的具体对象、当前职责及实际操作，再形成查询：例如表达模型收到什么任务，或输出数据经过哪段循环与条件；不能只检索“生成跑飞”“输出错误”。对象的训练用途、接口、状态与限制沿原件读取，标签只帮助找到资料。找到经验后，把其中条件与当前输入/做法逐项联系，明确它改变哪项判断或动作；读过而未采用不能算复用。原因未明时按 evidence-research 的 [诊断方法](../evidence-research/references/diagnosis.md) 追查实际链路，不因命中过去案例便断言同因。

理解任务涉及新对象、用途改变或现实变化时，用 `node integrations/context/objects.mjs recognize --query "名称" --purpose "当前用途"`（已知身份可用 `--id ID`）取得首轮已有认识：具体属性、类别共性、关系、来源变化与未知。默认每页12个指针，完整节点正文字符预算24000；`reading` 明示已读、预算延后、深度外和下页数量，按 `reading.next` 参数或目标ID继续取得，不把当前页当完整领域覆盖。来源 `readPointer` 只返回路径/URL、引用和段落定位，`contentReturned:false` 表示原证或领域长文正文尚未取得；用当前文件/网页工具读取实际内容后，才判断怎样采用。同名歧义先核身份，陌生名称给词面候选与类别导航，不自动创建或猜类别。预算只是材料读取控制，不是认知评分或固定认识表格；旧的已知低影响操作按当前条件复用已有认识，无须重读全套。

沿对象类别、运作方式和现实用途主动搜索会影响判断的共性与具体差异，不等出错或用户逐项指出。完整展开仍可用 `expand --id ID [--depth N]`，它会取得祖先类别、关联正文、knowledgeGaps及未展开关系，宽关系时优先按指针渐进取得。缺口清单只覆盖已登记且已读材料，AI还需发现尚未登记的联系。例如模型架构会联系总参数/激活参数、量化与内存，训练用途会联系输入方式和任务分工。保存这些因果和成立条件，不能只积累名词，或把示例属性套到所有同类对象。整体思路沿[对象认识与知识使用](../../workspace/memory/knowledge/对象认识与知识使用.md)，命令与边界沿[现用接口](../../modules/system/资料中心/object-knowledge/接口约定.md)。

形成的新认识及时接回现用对象库：共性原位补类别，可跨类别复用的知识补概念对象并建立有依据的关系，具体参数、职责和状态留具体对象。用原save/import版本接口保存来源、条件和未知，不另建一套登记；已有记录先合并。由当前AI判断这组知识是否已足够支持实际用途，邻接缺口可一并补齐，不规定固定搜索次数、展开深度或把全类未知查完才执行。后续同类对象复用类别知识，只有差异和变化才重新查证。

可沿导航直接读有关原件，也可用 `node integrations/context/recall.mjs search --query "当前完整任务或症状"` 统一查找知识、经验、错误、对象、资源和成果（字面+语义，默认10条并报总数，`--offset`翻页）；用户发话时hook已按原话送来前几条。知识卡再用 `node integrations/context/knowledge.mjs load --refs "所选ID"` 展开。关键词命中与自动少量候选只是线索，不是唯一入口、采用决定或研究覆盖；漏召可沿索引、已知路径、改写查询继续找，阅读数量由当前问题决定。load预算不足按返回的所需字符数提高，或沿原件范围续读；片段不等于完整卡。

采用前核经验的适用条件、实际结果与原证，配置声明也要分清授权、已有权益、可访问和实际运行。成功经验可能只解决局部，失败原因和旧修法也可能已经失效。没有适用办法、条件不符或关键证据不足时优先外部搜索；需选型或办法/效果会变化时，按 [evidence-research](../evidence-research/SKILL.md) 将当前任务与条件转成研究问题，查该领域成熟做法、真实反馈及失败条件，让证据改变当前做法；有本地经验也不省掉会改变选择的外部依据。搜索无关或入口失败就换路。脚本负责列出、查询、读取和存取材料，AI负责取舍与技术判断。报告实际采用或未采用的办法、原因和仍缺的证据，不由存取成功推定理解或长期效果。

确认被替代或无用的活动内容，按授权范围修正正文或退役，并保留原因、替代出处及一份冷恢复材料；个人清理用 `integrations/context/system-maintenance.mjs`，不递归删除。knowledge.mjs退役用于退出召回，历史追溯显式include-retired；不按年龄淘汰仍有效经验。压缩恢复或新执行者按自身任务判断需读什么，不把父代理已读视为孩子已读。

研究改变了做法、实际解决了问题、失败暴露可复用条件或用户纠正了旧动作时，主动把会改变下次工作的部分留进现用体系。领域事实沿已有知识说明或资料原件更新；具体经历按 [记法](../../workspace/memory/errors/WRITING.md) 保存触发、条件、动作、真实结果/边界与原证，先查同类案例再更新，避免重复。只发生在当前任务的进度留项目状态；没有新用途的调用与对话不另存经验，不固定每回合总结。

已核成功事实可用 `node integrations/context/knowledge-record.mjs --input "事实JSON路径"` 生成短卡与索引；需要独立条件、待验证状态或编辑旧卡时，复用 [同源知识服务](../../modules/system/资料中心/knowledge-service.mjs) 的 listCards/readCard/saveCard，保存前读当前原件，更新带返回的ref/version并留备份。服务直接写原experiences/errors，不是第二份库；聚合旧卡按原文件定点维护。未解决或尚未验证的改法明确标待验证；局部已证的案例把长期未验部分留在边界。保存后确认现用目录/检索能取得正文，技术效果仍沿原证与真实使用判断。

可跨相同条件复用的做法，在授权范围内按 [skill-creator](../.system/skill-creator/SKILL.md) 补入对应现用技能；重复确定性操作才提成脚本。案例保留具体证据，技能只保留改变以后动作的办法与适用条件，单例和第三方建议不直接变通用规则。后续使用以新结果和纠正更新同一原件，替换受影响的旧动作并留恢复材料；未证实只补边界，不伪造失败原因。下一次任务仍从完整目标选择、读原件并判断采用，不用保存、读取或模型自评证明长期进步。
