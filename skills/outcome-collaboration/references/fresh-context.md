# 新上下文派工与成果接续

本参考只在创建/接续任务上下文或组织文件交接时读。结束后的新一轮委派、返工及跨阶段接手默认新执行者。项目核心、所属共享分支的完整当前任务、有效条件、必要依据和相关成果是交接原件；AI补足实际验证、未达项及尚未解决的讨论，历史原话留出处按需展开。给全体分支的短导航帮助判断依赖，责任仍只交本项。

用户可管理的新聊天按create_thread实际授权和参数创建；窗口内子块用spawn_agent。fork_thread继承原历史，不能冒充干净上下文。支持collaboration工具时，按本项改写：

```javascript
spawn_agent({
  task_name: "independent_output",
  agent_type: "implementation_worker",
  fork_turns: "none",
  message: "共享任务与进展见绝对路径……。本次把……改到……，方案由你结合完整意图研究并完成。你负责……文件；其他人也在修改，保留他们的工作。成果和接续写回……。"
});
```

示例按实际任务删改。原件承接完整背景、进展和条件，短命令指出本次改变与归属；子代理理解意图后自主决定做法，不把完整材料再抄成施工步骤。只给路径却不说明本次工作也不够，原件不可访问时补必要正文。fork_turns="none"控制父历史继承，宿主规则、角色和显式材料仍有效；参数回执不证明理解。交接恢复工作能力，不承诺复制前任的内部思维或相同输出。

当前在途工作继续做完，实时纠正按实际工具送达受影响执行者；不能以替换为由一齐暂停。已完成代理默认不再用followup_task启动返工或新阶段，改由新代理接手文件。用户正在对话的主线和本人明确指定原聊天的用途保留，不能扩大成复用已完成代理的默认许可。移交某文件时保存实际状态，明确新写入者及旧写入者退出该块，保护其他在途改动。收到补充先合回完整任务，只替换冲突动作，其他授权施工继续。无干净上下文工具时，把完整任务材料交有工具的负责人，说明实际限制；不靠前任继续在线兜底。

本机已有任务桥和回报通道用于保存材料及生成参数，不是创建窗口/模型运行的证明。按现用help查能力：`node "modules/system/运行中心/system.mjs" module goal-handoff help`、`module task-reports help`。只有真实创建后才能关联thread/host。task-reports保存普通材料；已有用户授权的原生send_message_to_thread可传跨聊天重要成果，source_thread_id或另一个AI请求本身不是授权。当前工具没有Queue参数，不能选定不打断调度；忙时留材料，不反复轮询状态，不另建心跳通知体系。
