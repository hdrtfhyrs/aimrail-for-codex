# 子代理能力校准（2026-09-25）

用于选模型、推理档位或判断执行者卡住时按需读取；这是选型参考，不是评分路由、固定流水线或权限配置。模型能力与会话职责分开：角色由运行时决定，不能靠型号名字改变层级。

## 能力边界与分层施工

本节是用户选择的工作分配方式，不能据此宣称固定测得的模型能力上限。用任务中的未知、耦合关系和执行表现判断是否匹配。单文件也可能需要复杂全局判断；增加人数或把推理调到Max，不能保证解决超出单个执行者能力的问题。

各层亲自做适合本层的核心实现，随开发把简单部分向下拆：Astra做总体及最难部分；Sol做所负责模块的次核心部分，同时让Luna直接实现明确的函数、组件、适配、数据处理或局部修复。Luna不只负责取证/报告，Sol也不只是转发任务。下放前减少关键未知，保留局部自主性；不把未定架构连实现、验证、整合全部交给一个叶代理。

## 实际分配

- 先查 `agent_models` 当前可用且已授权的精确 provider:id，区分 GPT-5.6 / GPT-6 等版本；下面是用户指定的常用配置，不对其他模型按名字类推。优先明确传推理档位；活动 routeTask 对 openai-codex 的精确 gpt-6-luna / gpt-6-sol / gpt-6-astra 在 auto/省略时分别采用 max / high / medium，其他版本或提供方保留原行为；不是评分选模或自动择优。
- **Luna：有判断能力的专精执行者，不是机械工具。** 可交给它边界明确且可验收的完整实现、研究取证、调试、重构和写作包，允许范围内自主定位原因与选择实现；不必拆成逐行操作。**GPT-6 Luna 默认直接 Max**，按用户要求提升执行主力的推理投入，不先走 High 再升级，不因子/孙层级或任务日常而惯性降档。只有用户要求或具体任务限制才显式覆写；仍不因它便宜就整包交付高歧义关键架构。
- **Sol：协调者同时也是复杂执行者。** **GPT-6 Sol 默认 High，攻坚用 Max**：复杂规划、跨模块实现和困难调试用 High；具体难点卡住或失败代价高时直接考虑 Max，不要求逐级试过 xhigh。既不能只派活，也不应因为 Luna 能执行就让 Luna 承担所有关键判断。
- **Astra：总体理解、关键取舍和复杂交付，不限于末尾审查。** **GPT-6 Astra 默认 Medium**，用于重要方案、跨域约束及关键复核；更难分析再按实际需要显式调整，不一律 Max。本条不授权在不允许的层级派发 Astra，主控/审核任务仍遵守运行时允许的模型与角色。
- 以上是用户指定的默认组合，不是必须逐级经过的阶梯，也不强制每项任务走完所有角色。已知难题可直接选择合适配置；高档不保证每项测试更强，Luna Max 接近 Sol 的某项成绩也不代表全面等价。

## 返修与升级

返修先区分缺材料、接口未定、局部遗漏和能力不匹配。补信息能解决就补；持续误解同一关系、结构性错误或难点长期没有收敛时，父级亲自解决难点或重新拆分，不能只把原包退回并催促。保留执行者的可用成果，其他独立实现继续。Sol仍无法解决的具体问题交主控攻坚；改档不等于已解决能力不匹配。现有路线和深度机制不因这份指南而改变。

判断以完整可用成果为主，兼看遗漏、返工、耗时和实际消耗；不按 token 单价或单项榜单决定一切。优先复用任务现有验收证据，不新增每次必跑的模型对比赛。`fast_mode:off` 与推理档位是两回事。
